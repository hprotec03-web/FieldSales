# FieldSales mobile (Flutter - Android + iOS)

One shared Dart codebase. It talks to the same REST API and business rules as the web app
(assignment-based visibility, optional GPS, append-only follow-up outcome history).

> **Status:** the Dart sources in `lib/` and `test/` were written without a Flutter SDK available, so they have **not been compiled or run**.
> Expect to fix small compile errors on first `flutter analyze` (package-version API drift is the most likely cause).

## 1. Prerequisites
* Flutter SDK 3.22+ (`flutter doctor` must be green for the platform you target).
* **Android:** Android Studio + Android SDK (API 34+), an emulator or a device with USB debugging.
* **iOS:** a Mac with Xcode (15+), CocoaPods, an iOS simulator or a device and an Apple developer account for device/App Store builds. iOS cannot be built on Windows/Linux.

## 2. One-time project setup
The `android/` and `ios/` folders are generated by Flutter itself (they contain SDK-version-specific Gradle/Xcode files), then patched with the permissions this app needs:

```bash
cd mobile
bash tool/setup_platforms.sh                          # macOS/Linux
powershell -ExecutionPolicy Bypass -File tool\setup_platforms.ps1   # Windows (Android only is usable)
```
The script adds: Android `INTERNET/CAMERA/ACCESS_FINE_LOCATION/POST_NOTIFICATIONS` + notification receivers, a debug-only cleartext-HTTP allowance for `http://10.0.2.2`, and iOS usage strings (`NSCameraUsageDescription`, `NSPhotoLibraryUsageDescription`, `NSLocationWhenInUseUsageDescription`).

Then make two manual edits in `android/app/build.gradle(.kts)`:
```kotlin
android {
    defaultConfig { minSdk = 23 }                                  // flutter_secure_storage
    compileOptions { isCoreLibraryDesugaringEnabled = true }       // flutter_local_notifications
}
dependencies { coreLibraryDesugaring("com.android.tools:desugar_jdk_libs:2.1.4") }
```

## 3. Run
```bash
flutter pub get
flutter analyze && flutter test
# Android emulator (host machine is 10.0.2.2):
flutter run --dart-define=API_BASE_URL=http://10.0.2.2:8000
# iOS simulator:
flutter run --dart-define=API_BASE_URL=http://localhost:8000
# Physical device: use your computer's LAN IP, or a deployed HTTPS URL.
```
Start the backend first (see the root README) and sign in with a seeded account (e.g. `salesman1` / `Demo@12345`).

## 4. Release builds
```bash
flutter build appbundle --release --dart-define=API_BASE_URL=https://api.your-domain.com   # Android (Play Store); configure signing first
flutter build ipa --release --dart-define=API_BASE_URL=https://api.your-domain.com          # iOS, macOS only
```
Release builds must use **HTTPS**. Android signing: https://docs.flutter.dev/deployment/android - iOS: https://docs.flutter.dev/deployment/ios.
Publishing to Google Play / the App Store is a manual process that has **not** been performed.

## 5. Behaviour notes
* Token: stored with `flutter_secure_storage` (Android Keystore-backed / iOS Keychain). No cookies on mobile; the API accepts the JWT as a Bearer token.
* Salesmen see only customers **currently assigned** to them. When a manager reassigns a customer, the next refresh removes it (the API returns 404 for the old salesman).
* Salesmen cannot create customers directly; **New customer** opens the visit form in "new customer" mode, which creates the customer + visit (+ optional follow-up) in one server transaction and assigns the customer to the salesman.
* GPS and camera are requested only when you tap *Capture location* / *Take photo*. Saving a visit never requires either.
* Reminders: local notification 1 hour before a follow-up is due (best effort; requires notification permission).
