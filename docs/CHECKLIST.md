## Not verified / outstanding
1. **First-run verification** of everything: `pytest`, `npm run build && npm test`, `flutter analyze && flutter test`. Expect some small compile/type errors, especially in the web and Flutter code, which were never compiled.
2. **SQL Server**: no connection was ever made. Verify `alembic upgrade head` and `pytest tests/integration -m sqlserver` on a throw-away database. The migration is hand-written - run `alembic revision --autogenerate -m check` against a migrated DB and confirm it produces no diff.
3. **Dependency versions** are ranges, not pins (no package index access). After the first successful install run `pip freeze > backend/requirements.lock`, commit `package-lock.json` and `pubspec.lock`. Flutter plugin APIs (notably `flutter_local_notifications` 17.x, `geolocator` 13.x) drift between majors.
4. **`android/` and `ios/` folders** are generated by `mobile/tool/setup_platforms.*` (needs Flutter). Android needs the two manual Gradle edits in `mobile/README.md`. iOS must be built/tested on a Mac; physical-device testing and store publishing have not been done.
5. **Subsequent migrations:** only the initial migration exists.
6. **Business-rule confirmations needed:** duplicate-customer rule (default: same mobile in company), follow-up status transitions, salesman visibility of historical visits/follow-ups after reassignment (current: only while assigned), whether managers may create visits for any customer.
7. **Gaps / simplifications:** no platform-level super-admin or API to create companies (seed/CLI only); login rate limiter and token denylist are simple (single-node limiter); no PDF export; no password-reset/email flow; no audit-log table; file storage is local-disk only (abstraction provided); no pagination on assignment-history/outcome lists (small by nature); `Customer.Delete` removes only customers with no visits/follow-ups; web has no end-to-end (browser) tests; mobile reminders are local only (not synced across devices); no push notifications.
8. **Security review still required** before production: penetration/ASVS review, dependency audit (`pip-audit`, `npm audit`), WAF/rate limiting at the edge, CSP headers at the proxy.
